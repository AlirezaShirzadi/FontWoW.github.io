# راهنمای تست

FontWoW در حال حاضر تست خودکار تعریف‌شده در `package.json` ندارد. تا زمان اضافه‌شدن آن، هر
تغییر باید بررسی استاتیک، build و تست دستی متناسب با ریسک را پشت سر بگذارد.

## بررسی پایه

```bash
npm run lint
npm run build
```

## چک‌لیست smoke وب

- صفحهٔ اصلی و ویرایشگر بدون خطای console باز شوند.
- نوشتن و ویرایش متن، انتخاب فونت، رنگ، اندازه و تراز کار کند.
- افزودن، جابه‌جایی، چرخش، تغییر اندازه، تکرار و حذف لایه‌ها کار کند.
- undo/redo و ذخیره/بازیابی طرح رفتار مورد انتظار داشته باشد.
- آپلود فونت و تصویر فقط محلی بماند و بعد از reload طبق طراحی بازیابی شود.
- خروجی PNG تولید شود و هیچ کنترل، دستگیره یا selection UI داخل آن نباشد.
- کپی متن/تصویر و دانلود در مرورگرهای پشتیبانی‌شده بررسی شود.

## ماتریس رابط

حداقل تغییرات بصری را در این حالت‌ها بررسی کنید:

| حالت | بررسی |
| --- | --- |
| موبایل باریک | overflow، لمس، sheetها، safe spacing |
| دسکتاپ | چیدمان، hover/focus، اندازه بوم |
| فارسی RTL | ترتیب، تراز، اعداد و متن ترکیبی |
| English LTR | mirror صحیح و متن‌های کامل |
| reduced motion | حذف حرکت غیرضروری و حفظ کاربردپذیری |
| تم‌ها | کنتراست، focus و خوانایی |

## تست Android

برای تغییرات ذخیره فایل، clipboard، share، لینک خارجی، permission یا lifecycle:

- APK debug را build و روی دستگاه یا emulator اجرا کنید.
- اولین اجرا، بازگشت از background و اجرای offline را بررسی کنید.
- ذخیره تصویر و permissionها را روی نسخه‌های Android مرتبط آزمایش کنید.
- خطاهای JavaScript و native را در Logcat کنترل کنید.

## گزارش در Pull Request

دستورهای اجراشده، محیط آزمایش و سناریوهای دستی را بنویسید. برای تغییر بصری قبل/بعد و برای
رفتار تعاملی ویدئوی کوتاه مفید است. موارد تست‌نشده یا محدودیت محیط را صریح اعلام کنید.
